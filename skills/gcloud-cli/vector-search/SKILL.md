# gcloud vector-search — Vector Search (Agent Retrieval / Vector Search 2.0)

## Overview

`gcloud vector-search` manages Vector Search data objects for the collections-based Vector Search product — documented as **Agent Retrieval (formerly Vector Search 2.0)** — a self-tuning, fully managed, AI-native search engine (GA). You store JSON **data objects** inside **collections** (analogous to database tables, with optional JSON data schemas and vector schemas for dense/sparse embeddings), build ANN **indexes** over vector fields, and run semantic, text, or vector similarity **searches** — including autogenerated Vertex embeddings or bring-your-own-embeddings. Long-running work (collection/index lifecycle, imports/exports) is tracked through **operations**.

> Not to be confused with the original Vertex AI Vector Search (index/index-endpoint model), which is managed via `gcloud ai indexes` and `gcloud ai index-endpoints`.

## Quick reference — common workflows

### 1. Enable the APIs

```bash
gcloud services enable vectorsearch.googleapis.com aiplatform.googleapis.com \
    --project PROJECT_ID
```

### 2. Create a collection with a data schema and vector schema

```bash
gcloud vector-search collections create my-collection \
    --location=us-central1 \
    --display-name='My Collection' \
    --data-schema='{"type":"object","properties":{"year":{"type":"number"},"genre":{"type":"string"},"director":{"type":"string"},"title":{"type":"string"}}}' \
    --vector-schema='{"plot_embedding":{"denseVector":{"dimensions":3}},"genre_embedding":{"denseVector":{"dimensions":4}},"sparse_embedding":{"sparseVector":{}}}' \
    --project=my-project
```

### 3. Add data — single objects or bulk import from Cloud Storage

```bash
# Single data object
gcloud vector-search collections data-objects create my-do-1 \
    --collection=my-collection --location=us-central1 \
    --data='{"title":"My Movie","genre":"Drama","year":1994}'

# Bulk import (JSONL in a bucket in the same region)
gcloud vector-search collections import-data-objects my-collection \
    --location=us-central1 \
    --gcs-import-contents-uri=gs://my-bucket/contents/ \
    --gcs-import-error-uri=gs://my-bucket/errors/
```

### 4. Build an ANN index over a vector field

```bash
gcloud vector-search collections indexes create my-index \
    --collection=my-collection --location=us-central1 \
    --index-field='plot_embedding' \
    --display-name='My Index' \
    --filter-fields=genre,year --store-fields=title
```

### 5. Search the collection (semantic / text / vector)

```bash
# Semantic search (query text embedded server-side)
gcloud vector-search collections data-objects search \
    --collection=my-collection --location=us-central1 \
    --semantic-search-text="sci-fi" \
    --semantic-search-field="plot_embedding" \
    --semantic-task-type="retrieval-query" --top-k=5

# Plain text search over data fields
gcloud vector-search collections data-objects search \
    --collection=my-collection --location=us-central1 \
    --text-search-text="test" --text-search-data-fields="text_field" --top-k=10

# Vector search from a query vector file, using an index
gcloud vector-search collections data-objects search \
    --collection=my-collection --location=us-central1 \
    --vector-search-field="genre_embedding" --vector-from-file="vector.json" \
    --use-index="my-index" --top-k=7
```

### 6. Track long-running operations

```bash
gcloud vector-search operations list --location=us-central1

gcloud vector-search operations wait operation-1234567890 \
    --location=us-central1
```

## Common flags & tips

- **Everything is regional.** `--location` is required on essentially every command (e.g. `us-central1`); collections, data objects, indexes, and operations are all addressed as `projects/{project}/locations/{location}/...`. Fully qualified resource names can replace the ID + `--collection`/`--location` flags.
- **Long-running operations:** `collections create/update/delete`, `indexes create/delete`, and `import/export-data-objects` return operations. Add `--async` to return immediately, then use `vector-search operations wait/describe`.
- **Idempotency:** mutation commands accept `--request-id=UUID` — the server ignores duplicate requests with the same ID for 60 minutes (the zero UUID is not supported).
- **Optimistic concurrency:** data-object mutations support `--etag`; a mismatched etag blocks the change with an ABORTED error.
- **JSON filters:** `data-objects query/search/aggregate` filter with a MongoDB-style JSON expression, e.g. `--json-filter='{"genre": {"$eq": "sci-fi"}}'`.
- **Exactly one search mode** per `data-objects search`: semantic (`--semantic-search-text/-field/--semantic-task-type`), text (`--text-search-text/--text-search-data-fields`), or vector (`--vector-from-file/--vector-search-field`). Semantic/vector searches optionally take `--use-index=INDEX` or `--use-knn` (exact KNN engine).
- **Vectors format:** `--vectors` maps field names to either `dense` (`values` float array) or `sparse` (`indices` int array + `values` float array); accepts shorthand, JSON, or a YAML/JSON file.
- **Batch limits:** `batch-create`, `batch-update`, and `batch-delete` accept at most 1000 DataObjects per request; data object IDs must be 1–63 characters, RFC1035-compliant.
- **CMEK:** collections support customer-managed encryption via `--encryption-spec-crypto-key-name=projects/.../cryptoKeys/...` at create time.

## beta / alpha

A `gcloud beta vector-search` surface exists and mirrors the GA groups (`collections`, `collections data-objects`, `collections indexes`, `operations`); the GA reference page does not list an alpha surface. Pre-GA capabilities, when present, appear on the beta track first.
