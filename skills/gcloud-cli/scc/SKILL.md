# gcloud scc — Security Command Center

## Overview

Security Command Center (SCC) is Google Cloud's risk and security observability
platform: it surfaces vulnerability and threat **findings** generated by built-in and
third-party **sources**, sends new findings to Pub/Sub via **notification configs**, and
manages **posture** (org-policy) definitions and their deployments. The `gcloud scc`
command group reads and manages those resources through the Security Command Center API.
Enable the API once before running any command:
`gcloud services enable securitycenter.googleapis.com`.

Almost every command is scoped to a resource parent — `--organization`, `--folder`, or
`--project` (or a positional `PARENT` such as `organizations/123`). Org-level scope is
required for postures, posture-deployments, sources, and listing mute configs.

## Quick reference — common workflows

**List active findings across an organization**
```bash
gcloud services enable securitycenter.googleapis.com

# All ACTIVE findings under organization 123456, across all sources
gcloud scc findings list 123456 --filter="state=\"ACTIVE\""

# Narrow to one source and category
gcloud scc findings list 123456 --source=5678 \
    --filter="state=\"ACTIVE\" AND category=\"XSS\""

# Only emit specific fields (camelCase in the mask, not hyphens)
gcloud scc findings list 123456 --source=5678 \
    --filter="state=\"ACTIVE\"" \
    --field-mask="finding.category,finding.resource_name"
```

**Mute findings individually or in bulk**
```bash
# Mute / unmute a single finding (organizations/123/sources/456/findings/789)
gcloud scc findings set-mute 789 \
    --organization=organizations/123 --source=456 --mute=MUTED
gcloud scc findings set-mute 789 \
    --organization=organizations/123 --source=456 --mute=UNMUTED

# Bulk-mute everything matching a filter at org scope
gcloud scc findings bulk-mute --organization=organizations/123 \
    --filter="category=\"XSS_SCRIPTING\""
```

**Create and manage a static mute config**
```bash
gcloud scc muteconfigs create test-mute-config \
    --organization=123 --description="This is a test mute config" \
    --filter="category=\"XSS_SCRIPTING\""

gcloud scc muteconfigs list --organization=123
gcloud scc muteconfigs update test-mute-config --organization=123 \
    --filter="category=\"XSS_SCRIPTING\""
gcloud scc muteconfigs delete test-mute-config --organization=123
```

**Stream new findings to Pub/Sub (notification config)**
```bash
gcloud scc notifications create test-config --organization=123 \
    --pubsub-topic=projects/test-project/topics/notification-test \
    --filter="state = \"ACTIVE\""

gcloud scc notifications describe test-config --organization=123
gcloud scc notifications list 123
gcloud scc notifications update test-config --organization=123 \
    --pubsub-topic="projects/22222/topics/newtopic"
gcloud scc notifications delete test-config --organization=123
```

**Create and deploy a security posture**
```bash
# Create a posture from a YAML definition (parent is org + location)
gcloud scc postures create \
    organizations/123/locations/global/postures/posture-foo-1 \
    --posture-from-file=posture.yaml

gcloud scc postures list organizations/123/locations/global
gcloud scc postures describe \
    organizations/123/locations/global/postures/posture-foo-1

# Deploy a posture revision onto a target resource (org/folder/project)
gcloud scc posture-deployments create \
    organizations/123/locations/global/postureDeployments/posture-deployment-foo-1 \
    --posture-name=organizations/123/locations/global/foo-posture \
    --posture-revision-id=foo-posture-revision-id \
    --target-resource=projects/456

# Or extract a posture from an existing workload
gcloud scc postures extract \
    organizations/123/locations/global/postures/posture-foo-1 \
    --workload=projects/456
```

**Look up a source and update finding security marks**
```bash
gcloud scc sources describe 123456 \
    --source-display-name="Security Scanner"
gcloud scc sources describe 123456 --source=5678

# Replace all marks, then selectively update one mark
gcloud scc findings update-marks testFinding \
    --organization=123456 --source=5678 --security-marks="key1=v1,key2=v2"
gcloud scc findings update-marks testFinding \
    --organization=123456 --source=5678 --security-marks="key1=v1" \
    --update-mask="marks.key1"
```

## Common flags & tips

- **Scoping is mandatory** — almost every command targets a parent via
  `--organization`, `--folder`, or `--project` (formatted as `organizations/123` or just
  `123`). Many commands also accept a positional `PARENT` (e.g. `gcloud scc findings list
  123456`). `muteconfigs list` requires exactly one of the three flags;
  `postures`/`posture-deployments` require an org + `--location`.
- **Source selector** — `findings` commands take `--source=SOURCE` (the numeric source
  id; defaults to `-` = all sources). Resolve a source id from its name with
  `gcloud scc sources describe PARENT --source-display-name="..."`.
- **Mute states** — `findings set-mute --mute=` is one of `muted`/`unmuted`/`undefined`;
  `findings bulk-mute --mute-state=` is `muted`/`undefined`.
- **`--filter` for findings** uses SCC's API filter syntax (quote inner values), e.g.
  `--filter="state=\"ACTIVE\" AND category=\"XSS\""`, distinct from gcloud's client-side
  `--filter` on plain `list` output.
- **Field selection** — `findings list --field-mask` uses camelCase field paths
  (`finding.category,finding.resource_name`), not hyphenated flag names.
- **Security marks** — set with `--security-marks="k1=v1,k2=v2"`; pass an empty value
  (`--security-marks=""`) to clear all, or `--update-mask="marks.k1"` to touch one.
- **`--location`** defaults to `global`. Setting it explicitly routes the request to the
  SCC v2 API; required for non-global data-residency locations and for v2-created
  notification configs.
- **Defaults via config** — set `gcloud config set scc/organization 123` (and
  `scc/parent`) to avoid repeating the parent on every command.

## beta / alpha

`gcloud beta scc` and `gcloud alpha scc` exist. The beta surface largely mirrors GA for
**assets**, **findings**, **notifications**, **operations**, and **sources**. The
**postures**, **posture-deployments**, **posture-templates**, **posture-operations**,
**iac-validation-reports**, **bqexports**, **custom-modules**, and **manage** subgroups
appear only on the main (GA) `gcloud scc` surface. No core subgroup here was observed to
be alpha-only.
