# gcloud recommender — Recommender (Active Assist)

## Overview
`gcloud recommender` is the CLI surface for Google Cloud's **Recommender** service (part of **Active Assist**), which surfaces automated, actionable recommendations and insights across Cloud products. Recommendations are generated by per-product **recommenders** (e.g. VM machine-type rightsizing, idle resource cleanup, IAM policy reduction) and grouped into six value categories: cost, security, performance, reliability, manageability, and sustainability. Use it to list and inspect recommendations/insights for a project, billing account, folder, or organization, to drive them through their lifecycle states (claimed → succeeded/failed, or dismissed), and to tune the configuration of individual recommenders and insight types.

## Quick reference — common workflows

Enable the API first (one-time per project):
```bash
gcloud services enable recommender.googleapis.com
```

### List recommendations for a project
List VM machine-type (rightsizing) recommendations. Pick the recommender ID and location from the recommender catalog.
```bash
gcloud recommender recommendations list \
    --project=my-project \
    --location=us-central1-a \
    --recommender=google.compute.instance.MachineTypeRecommender
```

### Describe, claim, then mark a recommendation succeeded
The lifecycle uses an `--etag` for optimistic concurrency; read it from `describe`/output, then pass it to each state transition.
```bash
# 1. Inspect the recommendation (yields the current etag)
gcloud recommender recommendations describe RECOMMENDATION_ID \
    --project=my-project --location=us-central1-a \
    --recommender=google.compute.instance.MachineTypeRecommender

# 2. Claim it — signals you are applying it; freezes the content
gcloud recommender recommendations mark-claimed RECOMMENDATION_ID \
    --project=my-project --location=us-central1-a \
    --recommender=google.compute.instance.MachineTypeRecommender \
    --etag=abc123

# 3. After applying the change, mark it succeeded
gcloud recommender recommendations mark-succeeded RECOMMENDATION_ID \
    --project=my-project --location=us-central1-a \
    --recommender=google.compute.instance.MachineTypeRecommender \
    --etag=def456
```

### Dismiss a recommendation you do not want to act on
```bash
gcloud recommender recommendations mark-dismissed RECOMMENDATION_ID \
    --project=my-project --location=global \
    --recommender=google.compute.instance.MachineTypeRecommender \
    --etag=abc123
```

### List and accept firewall insights
Insights are the observations that back recommendations; they carry their own type ID and state machine.
```bash
# List firewall insights for a project
gcloud recommender insights list \
    --project=my-project --location=global \
    --insight-type=google.compute.firewall.Insight

# Mark a specific insight accepted
gcloud recommender insights mark-accepted INSIGHT_ID \
    --project=my-project --location=global \
    --insight-type=google.compute.firewall.Insight \
    --etag=abc123
```

### Tune a recommender configuration
```bash
# Inspect current config (positional RECOMMENDER, then read its etag)
gcloud recommender recommender-config describe \
    google.compute.instance.MachineTypeRecommender \
    --project=my-project --location=global

# Update from a YAML config file
gcloud recommender recommender-config update \
    google.compute.instance.MachineTypeRecommender \
    --project=my-project --location=global \
    --etag="123" --config-file=config.yaml
```

### Preview an insight-type config change
Use `--validate-only` to validate and preview without applying.
```bash
gcloud recommender insight-type-config update \
    google.compute.firewall.Insight \
    --project=my-project --location=global \
    --etag="123" --config-file=config.yaml --validate-only
```

## Common flags & tips

- **Entity scope (mutually exclusive, required):** every command targets exactly one parent — `--project=PROJECT_ID`, `--billing-account=BILLING_ACCOUNT`, `--folder=FOLDER_ID`, or `--organization=ORGANIZATION_ID`. (Note: `recommender-config` and `insight-type-config` support project / organization / billing-account, but not folder.)
- **`--location` is required** on every command. Use `global` for global recommenders/insights (e.g. firewall, IAM), or a specific zone/region for zonal/regional ones (e.g. `us-central1-a` for VM machine-type recommendations). The correct value depends on the recommender/insight type.
- **`--recommender` vs `--insight-type`:** recommendation commands take `--recommender=ID` (e.g. `google.compute.instance.MachineTypeRecommender`); insight commands take `--insight-type=ID` (e.g. `google.compute.firewall.Insight`). See the catalogs in the official docs for valid IDs.
- **`--etag` is required for every state transition and config update** (`mark-claimed`, `mark-dismissed`, `mark-failed`, `mark-succeeded`, `mark-accepted`, and `*-config update`). Read the current etag from the resource before writing.
- **`--state-metadata=KEY=VALUE,...`** attaches arbitrary metadata when transitioning recommendation/insight state (available on `mark-claimed`, `mark-failed`, `mark-succeeded`, `mark-accepted`).
- **`--validate-only`** on `recommender-config update` / `insight-type-config update` previews the change without persisting it.
- **Filtering & output:** `list` commands support the standard `--filter`, `--limit`, `--page-size`, `--sort-by`, and `--uri`. For example, surface only high-impact cost recommendations:
  ```bash
  gcloud recommender recommendations list \
      --project=my-project --location=global \
      --recommender=google.compute.instance.MachineTypeRecommender \
      --filter="primaryImpact.category=COST" \
      --format="table(name, primaryImpact.category, stateInfo.state)"
  ```

## beta / alpha

- **`gcloud beta recommender`** mirrors the GA surface (same four subgroups) with commands that may change without notice.
- **`gcloud alpha recommender`** adds extra lifecycle transitions: `mark-active` and `mark-dismissed` on the `insights` subgroup, plus `mark-active` and `mark-dismissed` on `recommendations`. The config subgroup is named `recommender-configs` (plural) in alpha versus `recommender-config` (singular) in GA. Use alpha only if you specifically need `mark-active` / `mark-dismissed` on insights.
